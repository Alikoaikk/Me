# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running the site

No build step. Serve `src/`:

```bash
make serve          # http://localhost:8080
```

Or open `src/index.html` directly in a browser. `system.html` must be
SERVED: its system (`js/system.js`) is an ES module with an import map
for the vendored three.js, and module scripts do not run from
`file://` (hud.js then shows the plain list instead).

`make check` verifies that every local `.js`/`.css` reference in the
pages resolves — run it after moving or renaming files.

## Layout

Everything the site serves lives under `src/`; `dist/` is generated by
`make build` and gitignored. See `README.md` for the full tree and
`docs/ARCHITECTURE.md` for how the pieces fit together, and
`docs/USER-STORY.md` for how the experience is meant to play.

- `src/*.html` — `index.html`, `projects.html`, `galaxy.html` (galaxy,
  name, profile), `system.html` (warp + the Koaik system; the launch
  link on galaxy.html opens it), `posts.html` and `activities.html`
  (reached from the top bar; empty for now), `beyond.html` (after the
  collapse)
- `src/css/` — `style.css` (shared, design tokens in `:root`), `galaxy.css`, `cursor.css` (the shared pointer)
- `src/js/` — `data.js`, `main.js`, `profile.js`, `hud.js`, `warp.js`, `system.js` + `emblems.js` (ES modules)
- `src/js/vendor/three/` — three.js r186, MIT, unmodified (core, module, OrbitControls)
- `src/js/galaxy/` — `galaxy.js` + `galaxy.legacy.js`
- `src/js/effects/` — `globe.js`, `fluid.js`

Pages reference assets relative to `src/` (`css/style.css`,
`js/effects/globe.js`). Those same paths work in `dist/`, because the
build copies `src/` to the deployed root.

## Key things to know

- **All content lives in `src/js/data.js`** (`window.portfolioData`).
  Edit there, not in the HTML.
- **`galaxy.legacy.js` is live code**, injected at runtime by
  `galaxy.js` when WebGL2 is unavailable. It is intentionally not in any
  `<script>` tag. It resolves against the script's own URL, so the two
  galaxy files must stay siblings.
- **`fluid.js` is currently unreferenced** — superseded by the galaxy
  hero, kept deliberately. Don't wire it up or delete it without asking.
- **Galaxy geometry is duplicated** between `galaxy.js` and
  `galaxy.css` (`NAME_FONT`, `NAME_CENTER_Y`, `ZOOM_PUSH`). Change both
  sides together.
- **Two star populations.** The live set (15.5k) is CPU-simulated and
  migrates in the burst; the field (48k) is GPU-only — placed once,
  rotated in the vertex shader, dissolves in the burst. Never add
  per-frame CPU work for the field; that is the whole point of it. Its
  cursor wake and spring run on the GPU via transform feedback
  (`simulateField`) as a port of `simulate()` — keep the two in step.
- **The volumetric dust is off** (`config.DUST: false`). The pass and
  its absorption compositing are intact behind the flag.
- **No CSS transitions on JS-driven properties.** `--burst` and the
  `--name-*` vars are eased in JS and written every frame; a transition
  on the consumer trails the canvas instead of smoothing it.
- **`patternAngle` advances only inside `simulate()`**, below the
  freeze check. Moving it anywhere else reintroduces a snap of the
  whole disc when the burst reverses.
- **Two pages since item 27.** `galaxy.html` is the galaxy, the name
  and the profile, and ends on the orbit mark (item 30; a link to `system.html`).
  `system.html` is the warp (`warp.js`) and the Koaik SYSTEM
  (`system.js` on three.js, `emblems.js` for the projects, `hud.js`
  for its text, the `.sys-*`/`.probe` blocks of `galaxy.css`): Koaik —
  a mini black hole (item 18) — at the centre, every project a living
  model of itself (not a planet) on its own orbit, free navigation.
  Its sky is `galaxy.js` again, in sky-only mode (`<html data-sky>`).
  Do not put three.js, the warp or the HUD back on `galaxy.html`: the
  user split them to keep the first page light. The waypoints trip
  that used to follow the planet was REMOVED on 2026-09-25 (item 14);
  do not resurrect it unasked.
- **`window.koaik`, not `window.planet`**: `<section id="planet">` is
  `window.planet` by named access, so the module's entry points are
  `window.koaik.arm()/reveal()` (warp.js calls them) and the test
  surface is `window.system`.
- **GitHub Pages must serve the built tree**, not the repo root — see
  the deployment note in `README.md`.

## Gotchas

- The education card hover is an opacity crossfade, not a 3D flip:
  `backdrop-filter` on the front face breaks `backface-visibility`.
- Scroll reveal is `.reveal` + IntersectionObserver in `main.js`;
  `projects.html` has none and renders instantly.
- Galaxy mouse events bind to the parent `<section id="hero">`, not the
  canvas, because the canvas sits behind `.hero-content`.

## Verifying visually

The Claude-in-Chrome extension was not connected in past sessions, so
all visual work is verified with the headless harness in
`tools/render/` — read its README first. Every render pass done so far
followed the same loop: render baseline → change → render → Read the
PNG → judge → iterate. Do not tune the galaxy blind; it overshoots in
one pass every time (too dim, then washed to white, then a magenta
wash — all happened). Two or three rounds is normal.

For "does X move/respond" questions use the deterministic A/B
(`ab-hover-det.js` + `diff.js`): a ratio of in-band to outside pixel
change above ~20× is a clean yes; the outside level should be ~0.1–0.3
(frame-identical runs). Non-seeded renders differ everywhere and prove
nothing.
